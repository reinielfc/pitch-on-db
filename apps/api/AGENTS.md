# AGENTS.md

> Scope: this file covers `apps/api` (Go backend) inside the `pitch-on-db` monorepo.
> Another independently runnable app exists at `apps/web`.

## Stack

- Language/runtime: Go 1.26 (`apps/api/go.mod`)

- Key frameworks: Gin + Huma (HTTP), Cobra + humacli (CLI), pgx via `database/sql` (Postgres)
- Entrypoint: `apps/api/cmd/service/main.go`

## Setup

Run commands from the monorepo root (`pitch-on-db/`).

- Install API dependencies: `make -C apps/api sync`
- Install API dev tools (golangci-lint): `make -C apps/api tools`
- Install root DB/codegen tools (sqlc, goose): `make tools`
- Start Postgres: `make start-postgres`
- Apply migrations: `make migrate`
- Run locally: `make -C apps/api run`
- Live reload: `make -C apps/api dev`

`apps/api` connects to Postgres at startup; `run`/`dev` fail if DB is not reachable.

## Before finishing any change

Use this local verify loop:

1. Regenerate artifacts when relevant:
   - `make sqlc` (after `db/queries` or `db/migrations` changes)
   - `make -C apps/api generate` (enums + mocks after domain/interface changes)
   - `make -C apps/api spec` (after HTTP route/schema changes)
2. `make -C apps/api lint`
3. `make -C apps/api test`
4. `make -C apps/api build`

## Architecture

- `cmd/service/` — composition root, CLI commands, server startup/shutdown, dependency wiring
- `internal/<domain>/` — domain model, command/query ports, service logic, generated enums/mocks
- `internal/platform/httpapi/` — HTTP handlers, DTOs, route registration, request middleware
- `internal/platform/postgres/` — DB adapter implementations, sqlc usage, row/domain mapping
- `internal/config/` — runtime options
- `internal/telemetry/` — structured logging setup
- `../../db/migrations`, `../../db/queries`, `../../db/sqlc.yml` — schema/query source of truth

Request flow: HTTP route (`httpapi`) -> `<domain>.Service`/`<domain>.QueryService` -> Postgres adapters -> generated `sqlc` queries.

## Conventions

- Keep business rules in `internal/<domain>/*`; keep `internal/platform/*` as adapters/mapping layers.
- Preserve read/write split: command path uses `Service` + `Repository`; read path uses `QueryService`.
- `<domain>.<Domain>` fields are private; adapters interact through `Snapshot()`/`Reconstitute()`.
- Register new endpoints through `With...Routes` and mount them via `WithGroupRoutes("/v1", ...)`.
- Use generated enum helpers + `internal/utils/enums` for enum/string conversions.

## Generated files — do not hand-edit

`make -C apps/api generate` runs both `enums` and `mocks`; use the
individual targets below to regenerate just one.

- `internal/platform/postgres/sqlc/*.go` — generated by `make sqlc` from `db/queries/*.sql` and `db/migrations/*.sql` (`db/sqlc.yml`)
- `internal/pigeon/domain_enumer.go` — generated by `make -C apps/api enums` from enum declarations in `internal/pigeon/domain.go`
- `internal/pigeon/mocks/*.go` — generated by `make -C apps/api mocks` from interfaces in `internal/pigeon/*` (`apps/api/.mockery.yaml`)
- `openapi.yml` — generated by `make -C apps/api spec` from registered Huma routes/schemas

If generated output diverges, edit the source-of-truth files and regenerate.

## Do not touch

- `internal/platform/postgres/sqlc/` — generated by sqlc
- `internal/pigeon/mocks/` and `internal/pigeon/domain_enumer.go` — generated code
- `bin/`, `tmp/`, `coverage.out` — local build/test artifacts (`apps/api/.gitignore`)

## Requires human approval before changing

- `../../db/migrations/*` — schema changes and rollback risk
- Public API contract changes (`internal/platform/httpapi/*`, `openapi.yml`) that are breaking
- Shared infra/config (`../../docker-compose*.yml`, `../../infra/**`, `../../Makefile`)
